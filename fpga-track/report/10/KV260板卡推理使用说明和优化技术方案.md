# KV260板卡推理使用说明和优化技术方案



# 1 使用说明

## 文件说明

- linux镜像文件夹：包含一个可烧录的Linux镜像文件。
- PS文件夹：PS侧的llama.cpp中推理服务完善和优化的源代码，以及编译好的可执行服务文件。
- PL文件夹：PL侧的自定义IP核源代码，以及自定义IP核平台的bitstream、设备树、shell配置文件、平台xsa文件以及IP核源代码编译文件。
  - 自定义IP核烧录文件：存放可烧录到KV 260开发板中的文件，包含bitstream、设备树文件、shell配置文件。
  - 自定义IP核源码：存放所有自定义IP核的源代码文件。

- 测试Json文件文件夹：包含通过4种测试代码运行出来的4个测试结果文件。
- 测试报告和技术文档：包含测试报告文件和技术文档。
- 复现视频：存放复现视频。

## PL侧的自定义IP核烧录和加载方法

1. 使用镜像烧录

在Linux镜像文件夹中包含三个镜像分卷文件，解压第一个压缩包后，会自动组合成完整的Linux镜像文件kv260_portable_system.img.gz。在Raspberry Pi Imager工具中选择该镜像并选择自己的SD卡，将该镜像烧录到自己的SD卡中，并在开发板中插入SD卡并进行通电和加载。

2.  使用bitstream 

在/lib/firmware/xilinx/文件夹下创建一个FPGA平台名，如kv260_accel。在PL/自定义IP核烧录文件/中将自定义IP核的bitstream、设备树以及shell配置文件复制到/lib/firmware/xilinx/kv260_accel中，可通过下列命令实现。

sudo mkdir -p /lib/firmware/xilinx/kv260_accel

sudo cp kv260_accel.bit.bin /lib/firmware/xilinx/kv260_accel/design_1_wrapper.bit.bin

sudo cp kv260_accel.dtbo /lib/firmware/xilinx/kv260_accel/kv260_accel.dtbo

sudo cp shell.json /lib/firmware/xilinx/kv260_accel/shell.json

3. 在KV 260开发板上加载自定义IP核

（1）在KV 260开发板上查看可加载的FPGA平台，可以看到自定义的平台，如上述创建的kv260_accel

sudo xmutil listapps

（2）卸载现在正在运行的FPGA平台

sudo xmutil unloadapp

（3）加载自定义平台

sudo xmutil loadapp kv260_accel

## PS侧llama.cpp使用

可以选择已经提供好编译好完整的推理服务，在/PS/llamacpp/bulid/bin/中的llama-server模型加载和推理服务。也可以选择自定义进行编译。

### 编译命令

PS侧推理优化方法是基于llama.cpp进行实现。为了使用这些优化方法，编译时启用ARM优化，因此需要重新编译使用llama-server，当然我们也提供了编译好的llama-server在build/bin/文件夹中。整个编译命令如下：

```
mkdir build && cd build
cmake .. -DLLAMA_BUILD_SERVER=ON -DLLAMA_KV260=ON -DGGML_NATIVE=ON -DCMAKE_BUILD_TYPE=Release
make -j$(nproc)
```

### llama-server运行时配置

启动llama-server命令如下：

```
./llama-server -m ../gguf/SmolVLM2-500M-Video-Instruct-Q8_0.gguf --mmproj ../gguf/mmproj-SmolVLM2-500M-Video-Instruct-Q8_0.gguf >./llama-server.txt --ctx-size 4096
```

# 2 PS侧优化方法说明

首先Cortex-A53是顺序执行（In-Order）微架构，其计算瓶颈并非 FLOPS 不足，而是Cache Miss 与内存延迟导致的流水线停顿。因此，本优化方案提出通过软流水、预取、内存池化与线程绑核，消除 CPU 停摆挑战，在相同规模的输入和输出token量情况下，减少prefill和decode阶段的时间开销。

## 优化一：NEON核心算子软流水 + 硬件预取

### 实现原理

ARM Cortex-A53处理器没有乱序执行功能，在默认循环中加载数据时会阻塞后续MAC指令。通过以下技术可以隐藏内存延迟，使NEON计算单元持续满载：

1. 使用`__builtin_prefetch`提前拉取下一块数据
2. 循环展开实现软流水线
3. 利用NEON指令并行计算
4. 深度预取以进一步隐藏内存延迟
5. 分块处理以优化缓存利用率

### 实现细节

在`llama.cpp\ggml\src\ggml-cpu\ggml-arm-opt.c`文件中修改了`ggml_vec_dot_f32_opt`函数，增加了ARM NEON优化版本：

另外实现了优化的`ggml_gemm_f32_8x8_neon`函数，具有以下增强功能：

1. L2缓存感知的分块处理
2. 更深的循环展开
3. 改进的预取策略
4. 线程绑核优化

## 优化二：Decode零分配内存池

### 实现原理

默认llama.cpp每生成1个token都会调用malloc分配临时计算buffer。ARM Cortex-A53的内存分配器延迟高达0.5~1.2ms，累积后显著拖慢Decode过程。改为预分配固定大小的Decode专用内存池，彻底消除分配开销。

### 增强实现细节

增强了内存池功能，包括：

1. 线程安全的内存池实现，使用互斥锁保护
2. 动态大小调整，根据模型参数自动计算所需内存
3. 重置功能，确保每次解码前内存池是干净的
4. 优化的内存对齐功能

同时提供了一个辅助函数`llama_enable_decode_memory_pool`，用户可以在初始化context后调用此函数来启用内存池功能。

## 优化三：L2感知分块 + 线程硬绑定

### 实现原理

ARM Cortex-A53的4核共享1MB L2 Cache，默认线程池会动态调整任务块大小并迁移核心，导致L2频繁失效与上下文切换。改为固定L2适配块大小 + 绑核调度。

### 增强实现细节

1. 更精确的L2块大小计算，考虑了最小阈值
2. 线程绑核功能，防止线程迁移
3. Prefill和Decode阶段的差异化优化策略
4. API接口暴露给外部使用

## 算子检测和分发

在ggml_backend_kv260.cpp中初始化计算图，对计算图进行检测分析，针对注意力计算、加权计算等矩阵乘法进行分块计算，以及算子融合，分析完成通过操作符进行标识。在获取计算标识符后在 kv260_interface.cpp实现寄存器配置，以及标量预填充寄存器。完成后在pl_controller.cpp中进行中断控制和分发，后续执行在FPGA的加速核计算优化中执行计算操作。

# 3 PL侧优化方法-自定义IP核推理优化

自定义4个加速核和1个控制核。具体的IP核作用如下。

### 控制调度器IP核（pl_controller.cpp）

该控制IP核作为整个编程逻辑加速子系统的中央调度器，负责管理协调与处理器系统的底层通信，并将各项具体的计算任务进行分发给各个专用的硬件加速自定义核。具有的功能特性包含如下：

- 门控指令原子拼接：通过AXI-Lite接口实现检测来自PS侧的的写信号。
- 描述符大突发预取：控制器检测到门铃FIFO非空时，通过AXI Master接口项连续内存管理区的描述符环发起对齐的单次大突发读取，极大的提升任务元数据的加载效率。
- 多核分发与轮询：描述符中的操作符后，通过控制总线直接配置并启动对应的加速核，并对子核的状态寄存器进行轮询，等待其完成。
- 高性能写回和中断机制：子核运行完成后，控制器通过HPC端口写回完工ID。
- 硬件看门狗机制：能够捕捉子核中的死锁等异常状态并自动进行错误处理和降级清空，增强系统的鲁棒性。

### 分块注意力机制IP核（kernel_attn_block.cpp）

该加速核是一个优化的注意力机制的硬件流式实现，独立完成包含$QK^T$分块矩阵乘法、块Softmax计算以及$PV$矩阵乘法的全套自注意力实现。该加速核的功能特征如下：

- 分块注意力：采用高度细分的分块策略，通过逐块的预取、计算和写回来限制片上缓存的边界，极大控制了硬件资源的开销。

- 旋转位置编码流式注入：提前构造cos/sin常量查找表（LUT），在Q和K流经管道时，能偶全吞吐速度进行实时在二维复数平面上进行位置编码的旋转映射。

- 硬件级块Softmax引擎：预构建指数函数的查找表。硬件流水线受限在行中擦护照最大值来保证数值的稳定性，然后计算差值并通过查找表与倒数进行乘法归一化，将注意力分数转化为INT8输出。

### 二维脉动阵列通用矩阵乘法计算IP核（kernel_gemm_int8.cpp）

该加速核是一个深度优化的INT8通用矩阵乘法加速引擎，专门用于视觉语言大模型中计算量占比最高的密集矩阵乘法。加速核的共功能特性如下

- 采用高效的32×32脉动阵列架构，让激活数据和权重数据在阵列维度流式流动，实现极高的数据复用率，最大限度减少对片外内存的访问。

- 实现2-way物理点积打包：通过重构k轴计算逻辑，将k轴的步长改为2从而实现两路并行点积。将两个有符号的点击算子通过，在单科DSP中实现同时计算两组INT8乘加，在计算吞吐量实现翻倍。

### ViT MLP算子融合IP核（kernel_fused_vit_mlp.cpp）

该加速核是一个专为视觉语言大模型中ViT的多层感知机（MLP）定制的融合计算内核，通过算子融合将Linear1->GELUTanh激活函数->Linear2三个对立的层级操作融合在一条紧密融合的硬件流水线中，消除中间特征数据仿反复写入核读取片外DDR造成的系统带宽瓶颈。

### 均方根归一化IP核（kernel_rmsnorm.cpp）

该加速核实现了大模型中广泛使用替代传统LayerNorm的算子，提供了一个高度流水线化、端到端的硬件物理闭环，在一个连续的数据流中完成全套的归一化和哈达玛重缩放。
