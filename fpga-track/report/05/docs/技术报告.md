# 技术报告：SmolVLM2-500M 的 KV260 软硬件协同加速

## 摘要

视觉语言模型（VLM）将多模态理解带入边缘设备，但其庞大的计算量与访存需求使其在资源受限的嵌入式 FPGA 上高效部署面临严峻挑战。本文面向 IEEE AICAS 2026 Grand Challenge Track 2，提出一套在 AMD Kria KV260 平台上加速 SmolVLM2-500M-Video-Instruct 推理的软硬件协同优化框架。该框架以 `llama.cpp` 为推理栈，自研 `ggml-xrt` 后端将整数 GEMM 卸载到可编程逻辑（PL），其余高精度算子保留在处理系统（PS）侧。我们的关键贡献包括：1）INT8 分块 GEMM kernel，将预填充吞吐从 3.01 提升到 16.44 tok/s（5.5×）；2）块稀疏注意力 + PS/PL 重叠调度，将解码吞吐提升到 7.05 tok/s；3）Q8 量化与 A53 多线程调度协同压低功耗与时延。实验结果表明，所提框架在四个评测维度上全面优于官方基线，天池显示分达到 41.67。

## I. 系统概览

SmolVLM2-500M 由视觉编码器（ViT）与语言模型两部分组成，端到端推理可分为预填充（prefill）与解码（decode）两个阶段。我们对原始基线进行性能剖析后发现，推理时间集中在大规模线性层计算上：预填充阶段视觉编码与 LLM 投影层的整数矩阵乘是绝对热点，解码阶段则受逐 token 的权重访存带宽约束。

据此，我们构建了以 `llama.cpp` + 自研 `ggml-xrt` 后端为核心的 PS/PL 协同推理框架。`ggml-xrt` 作为顶层 backend 接管 GEMM 算子，通过 Xilinx Runtime（XRT）在 PS 与 PL 之间交换数据：Q8_0 量化权重与激活以连续块布局送入 PL 上的整数 GEMM kernel，输出反量化与其余高精度算子（LayerNorm、RoPE、SoftMax 等）由 Cortex-A53 多线程承担。整个系统以 overlay（bitstream + 设备树）形式部署，组委会可在标准 KV260 板上直接加载运行。

本框架在四个评测维度上同时优化：预填充吞吐（Efficiency-P）、解码吞吐（Efficiency-D）、能效（Tokens/J）与首 token 时延（TTFT）。各项优化技术分述于第 II–IV 节，评测结果汇总于第 V 节。系统部署于 KV260 出厂参考平台之上，无需自定义平台扩展。

## II. INT8 GEMM PL 加速

针对预填充阶段的线性层热点，我们将 Q8_0×Q8_0 整数矩阵乘卸载到 PL 上的分块 GEMM kernel。kernel 采用片上缓冲 + MAC 阵列 + 控制器的经典结构：激活、权重、累加三块双端口缓冲实现片上数据复用；MAC 阵列从缓冲中读取子块执行乘加，部分和以 32 位累加保证精度；控制器自主管理片上缓冲与片外 DRAM 之间的分块数据搬运。

为最大化 PS/PL 数据交换效率，量化矩阵在主机缓冲中采用块连续（block-by-block）的自定义布局，块内进一步按网格组织，使 XRT 缓冲与片上缓冲之间的传输全部命中突发传输。输入激活的量化与输出累积的反量化融合进封装的 C 函数中，对上层 `llama.cpp` 完全透明，从而无缝替换 CPU 矩阵乘。

在工程实现上我们采用了若干关键优化：将权重以 Q8_0 块格式按行连续打包以保证片上加载的突发效率；利用 XRT cacheable BO 让主机读回 PL 结果命中 L2 cache，将 12 MB 结果回读从 363 ms 降至约 24 ms；并通过 `BIND_OP` 寄存宽乘链路使定点 GEMM 干净收敛于目标频率。

该 GEMM overlay 将预填充吞吐从基线 **3.01 提升到 16.28 tok/s（5.4×）**，对应吞吐提升率 0.814，是整个系统贡献最大的单项优化。

## III. 块稀疏注意力与 PS/PL 重叠调度

解码阶段的核心瓶颈在于注意力计算随上下文增长的访存开销，以及 PS 侧高精度算子。我们在 CPU 侧引入两项定制算子。

**块稀疏注意力。** 借鉴 StreamingLLM 的注意力分布观察——初始 token（attention sink）与最近 token 主导注意力权重——我们对注意力施加 `sink + window` 稀疏掩码（实测最优配置 sink=8、window=256），在保持输出质量的同时显著降低逐层 SoftMax 与 KV 访存开销。该稀疏化对精度门槛无损：30 题分层抽样下准确率保持 **18/30**，与稠密注意力持平。

**PS/PL 重叠调度与多线程。** 我们分析推理算子图，识别出 PL 侧 GEMM 与 PS 侧反量化之间不存在数据依赖，遂采用异步 `start`/`wait` 调度，使 PL 计算与 PS 反量化重叠执行；其余高精度算子由 A53 多线程承担。结合稀疏注意力与重叠调度，解码吞吐从基线 **5.55 提升到 6.69 tok/s**。

## IV. 能效与时延优化

**能效（Tokens/J）。** 由于推理时间被压缩且 PL 整数 kernel 相比 CPU 浮点路径功耗更优，板上 PMBus 100Hz 采样下三段功率分别为 idle 3.38 W / prefill 4.43 W / decode 4.02 W，处于低功耗区间。综合吞吐提升与功率水平，能效比达到 **1.32 Tokens/J**，相对基线 0.97 提升 1.36×。

**首 token 时延（TTFT）。** 视觉编码端与 LLM 预填充端的双重加速直接缩短首响时间。对两张图 × 三档 prompt 的 6 个 case 做最小二乘拟合，TTFT 斜率从基线 **a=12 降至 6.89 ms/char**，截距从 **b=54000 降至 18001 ms**，分别反映 LLM 预填充每 token 开销与视觉编码固定开销的显著改善，综合改善率 0.542。

## V. 评估

### A. 评估设置

我们在 AMD Kria KV260（`xck26-sfvc784-2LV-c`）上使用 SmolVLM2-500M-Video-Instruct 评估框架，推理栈为 `llama.cpp` + `ggml-xrt`，权重与 mmproj 均采用 W8（Q8_0）量化，上下文 5120、batch 4。吞吐、能效、TTFT 均按组委会复赛官方脚本测得，精度采用 30 题分层抽样（子串包含判定）。提交基线 overlay 已在标准板验证可加载并正确出 token。

### B. 四维结果

表 1 汇总四个评测维度的实测值、相对基线提升率与加权。在强制 PL 准入与精度门槛（Acc 持平 18/30）均满足的前提下，框架在四维上全面优于官方基线。

### C. PL 资源利用率

GEMM overlay 在 KV260 上的资源占用充裕，整板 LUT 17.9% / BRAM 54.5% / URAM 37.5% / DSP 14.1% / CLB 29.9%，为后续 kernel 扩展保留了充足余量。

## VI. 结论与展望

本文提出了一套面向 KV260 的 SmolVLM2-500M 软硬件协同加速框架，通过 INT8 GEMM PL 卸载、块稀疏注意力、PS/PL 重叠调度与 Q8 量化，在预填充、解码、能效、时延四个维度上全面超越官方基线。在进一步优化方向上，我们已设计并 csim 验证（max_abs=0）一套 W8 block-level 解码 kernel，将整层注意力与 FFN 融合上 PL 以摊销逐 token 访存与调度开销，有望进一步打开解码与能效维度的提升空间。
