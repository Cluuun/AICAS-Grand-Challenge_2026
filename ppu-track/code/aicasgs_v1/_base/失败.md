# 已验证失败或负收益优化（写入受限版）

> 说明：用户原本希望写入仓库根目录 `失败.md`，但当前仓库规则只允许修改 `evaluation_wrapper.py` 和 `_base/`，因此本文档写入 `_base/失败.md`。

## 1. AWQ + FP8 KV cache 路线失败

### 1.1 `FLASH_ATTN + fp8 kv cache`
失败原因：
- 当前 vLLM 0.20.1 下，`FLASH_ATTN` 与 `kv_cache_dtype=fp8` 不兼容

典型报错：
- `Selected backend AttentionBackendEnum.FLASH_ATTN is not valid for this configuration. Reason: ['kv_cache_dtype not supported']`

结论：
- **当前 A6000 环境下，AWQ 主路径不要启用 FP8 KV cache。**

### 1.2 `TRITON_ATTN + fp8 kv cache`
失败原因：
- A6000 (SM86) 上 Triton FP8 类型/架构支持不足

典型报错：
- `type fp8e4nv not supported in this architecture`

结论：
- **A6000 + 当前 vLLM 版本不适合作为 FP8 KV 主路径。**

## 2. 文本 `TORCH_SDPA` backend 不可用

在当前 vLLM 版本与当前平台上，文本 `TORCH_SDPA` backend 未正确注册。

典型报错：
- `Backend TORCH_SDPA must be registered before use`

结论：
- **不可作为文本 attention backend 候选。**

## 3. 已验证负收益的非量化优化

### 3.1 `use_prefill_decode_attention=1`
文件：
- `result_awq20_triton_sdpa_prefilldecode_gpu1.json`

结果：
- TTFT：55.83 ms
- Throughput：264.15 tok/s
- 命中率：40.00%

对比基线：
- TTFT 更差
- Throughput 更差

结论：
- **负收益，不建议开启**

### 3.2 关闭 `prefix caching`
文件：
- `result_awq20_triton_sdpa_noprefix_gpu1.json`

结果：
- TTFT：56.18 ms
- Throughput：253.63 tok/s
- 命中率：40.00%

结论：
- **明显负收益，必须保留 prefix caching**

### 3.3 `max_model_len=768`
文件：
- `result_awq20_triton_sdpa_len768_gpu1.json`

结果：
- TTFT：55.13 ms
- Throughput：260.27 tok/s
- 命中率：40.00%

结论：
- **比 1024 更差**

## 5. speculative decoding 失败/负收益

### 5.1 `ngram speculative decoding`
文件：
- `result_awq20_triton_sdpa_ngram_gpu1.json`

结果：
- TTFT：55.94 ms
- Throughput：105.81 tok/s
- 命中率：40.00%

结论：
- **严重负收益**
- 吞吐接近腰斩以上
- 不建议启用

### 5.2 `suffix speculative decoding`
文件：
- `result_awq20_triton_sdpa_suffix_gpu1.json`

结果：
- TTFT：42.06 ms
- Throughput：145.65 tok/s
- 命中率：40.00%

结论：
- TTFT 较低，但吞吐远低于基线
- 若目标是提高吞吐量，则**仍属负收益**

### 5.3 `suffix decoding` 初始依赖缺失
初始失败原因：
- 缺少 `arctic-inference==0.1.1`

典型报错：
- `ImportError: Arctic Inference is required for suffix decoding.`

后续已安装依赖并补跑，最终证明虽然可运行，但吞吐仍显著低于基线。

## 6. FLASHINFER 路线初始环境失败点

在未修复 conda 环境前，FLASHINFER 初始失败原因：
- JIT 链接阶段找不到 `-lcuda`

典型报错：
- `ld: cannot find -lcuda`

后续修复方式：
- 向 `$CONDA_PREFIX/lib64` 和 `$CONDA_PREFIX/lib64/stubs` 补充 `libcuda.so` 链接

说明：
- 这是**环境修复成功案例**，不是模型优化失败；但不修复时确实无法跑通。

## 7. 当前不建议保留的项总表

- FP8 KV cache（AWQ 路线）
- 文本 `TORCH_SDPA` backend
- `use_prefill_decode_attention=1`
- `prefix_caching=0`
- `max_model_len=768`
- `FLASHINFER prefill on`
- `use_trtllm_attention=1`
- `ngram speculative decoding`
- `suffix speculative decoding`（若目标是吞吐提升）
