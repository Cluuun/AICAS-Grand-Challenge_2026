## 3. 已验证的有效工程手段

### 3.1 修复 FLASHINFER 的 JIT 链接环境

在 `aicas_vllm_fp8` 环境里，FLASHINFER 初始失败点为：
- `ld: cannot find -lcuda`

有效修复方法：
```bash
mkdir -p "$CONDA_PREFIX/lib64/stubs" "$CONDA_PREFIX/lib64"
ln -sf /usr/lib/x86_64-linux-gnu/libcuda.so "$CONDA_PREFIX/lib64/libcuda.so"
ln -sf /usr/lib/x86_64-linux-gnu/libcuda.so "$CONDA_PREFIX/lib64/stubs/libcuda.so"
```

配套运行环境：
```bash
export NCCL_SO=$CONDA_PREFIX/lib/python3.10/site-packages/nvidia/nccl/lib/libnccl.so.2
export LD_PRELOAD=$NCCL_SO
export VLLM_NCCL_SO_PATH=$NCCL_SO
export VLLM_ENABLE_V1_MULTIPROCESSING=0
export VLLM_WORKER_MULTIPROC_METHOD=spawn
```

修复后：
- `FLASHINFER + MM TORCH_SDPA` 可稳定跑通 20 样本

### 3.2 保持 `prefix_caching=1`

这是当前最优配置的必要条件之一。

### 3.3 保持 `skip_mm_profiling=1`

当前最佳配置中始终保留该项，避免无意义的多模态 profiling 开销。

## 5. 最终建议

### 如果目标是吞吐量最高
用：
- `TRITON_ATTN + MM TORCH_SDPA`

### 如果目标是 TTFT 最低
用：
- `FLASHINFER + MM TORCH_SDPA`

### 如果只保留一套默认配置
优先保留：
- `TRITON_ATTN + MM TORCH_SDPA`

原因：
- 吞吐最高
- 准确率不劣化
- 兼容性最好
- 对环境依赖少于 FLASHINFER


## 6. speculative decoding 探索结论

### 6.1 ngram speculative decoding
- 文件：`result_awq20_triton_sdpa_ngram_gpu1.json`
- TTFT：55.94 ms

- TTFT：42.06 ms
- Throughput：145.65 tok/s
- 命中率：40.00%
- 结论：TTFT 较低，但吞吐远低于基线；若目标是提高吞吐量，则**不建议启用**
