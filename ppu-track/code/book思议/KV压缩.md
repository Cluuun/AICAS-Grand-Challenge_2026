长上下文、多图输入、长视频理解、GUI 交互……这些能力，已经越来越像多模态大模型和大语言模型的“标配”了。但能力一旦拉长，系统侧最先吃不消的，往往不是参数量本身，而是推理阶段一路膨胀的 KV Cache：显存占用上去，带宽压力变大，延迟也跟着变高。于是，如何在不明显伤害性能的前提下压缩 KV，成了近来 VLM / LLM 推理优化里的一个核心问题。

围绕这个问题，社区已经提出了不少 KV Cache 压缩方法。不过，大多数方案默认了一个并不总成立的前提：只要把“重要”的 KV 留下来，压缩结果就足够好。 问题在于，“重要”不等于“覆盖全面”。如果留下来的 KV 虽然分数都很高，却彼此高度相似，那么模型看似保住了重点，实际上却可能丢掉对整体语义分布的覆盖，尤其是在视觉语言场景里，这种冗余问题往往更明显。

最近，来自上海交通大学 EPIC Lab、四川大学和华中科技大学的研究团队提出了一个很有意思的方案——MixKV。顾名思义，MixKV 的关键就在这个 “Mix” 上：它不再只盯着 importance，而是进一步把 diversity 也纳入压缩目标，并根据不同 attention head 的冗余程度，自适应决定该更看重“重要性”还是“多样性”。这种思路本质上是在回答一个更深一层的问题：KV 压缩优化的，究竟只是“单点价值”，还是“整体覆盖”？ MixKV 给出的答案是：两者都要。

TL;DR：MixKV 是一个可插拔的 KV Cache 压缩增强框架。它通过 head-wise 的自适应 mixing，把 importance 和 diversity 联合纳入压缩目标，让 KV 压缩不再只是“挑最重要的”，而是进一步做到“保重点，也保覆盖”。

一、问题出在哪：只保“高分 KV”，未必保住了完整信息
现有 KV 压缩方法大多围绕 importance 展开：谁更关键，就优先保留谁。这个思路没有错，但它默认不同 KV 之间的“重复度”不是主要问题。

而在视觉语言模型里，事情恰恰没这么简单。

图像 token 天然带有更强的局部重复结构，不同 attention head 的冗余程度也并不一致。于是，单纯依赖 importance，很容易保留一批“都很重要、但彼此很像”的 KV，最后看起来预算没少花，真正保留下来的信息覆盖却并不够广。






MixKV 先做了一件很关键的事：不是直接提出新方法，而是先分析现象。

论文发现，LVLM 中的 KV 冗余结构比纯文本模型更复杂，而且这种冗余是 head-wise 异构 的。也就是说，有些 head 更容易聚集相似信息，有些 head 则需要更分散的保留策略。

这也意味着，所有 head 用同一套压缩逻辑，并不合理。

二、MixKV 怎么做：把“重要性”和“多样性”一起纳入目标
MixKV 的核心并不复杂，可以概括成两步：

1）同时看 importance 和 diversity
importance 负责回答：哪些 KV 更关键；

diversity 负责回答：哪些 KV 与其他已选 KV 更不相似、更能补充覆盖。

这一步的意义在于，避免压缩预算被重复语义反复占用。
如果一堆 KV 都集中表达同一块信息，那么继续保留更多同类样本，边际收益其实是很低的。

2）按 head 的冗余程度自适应混合
MixKV 并不是固定比例地把两种分数加在一起，而是先估计不同 head 的冗余水平，再决定这个 head 更该偏向 importance，还是更该偏向 diversity。

冗余高的 head，更需要 diversity，避免反复保留近似信息；
冗余低的 head，则仍然更依赖 importance，避免把真正关键的 KV 稀释掉。
这也是 MixKV 最值得注意的地方：

它不是“一把尺子压所有 head”，而是让不同 head 用更合适的压缩偏好。






从工程角度看，这种设计也很友好。

因为 MixKV 并不要求你重写已有压缩器，而是能直接叠加在 SnapKV、AdaKV、PyramidKV 等方法之上，属于很典型的 plug-and-play 增强模块。

三、实验说明了什么：它不是某一项特例，而是整体更稳
1）多模态理解任务上，预算越紧，收益越明显
在 LLaVA-NeXT-Mistral-7B、InternVL3-8B、Qwen2-VL-7B-Instruct 等模型上，MixKV 在 DocVQA、OCRBench、TextVQA、ChartQA、TextCaps 等基准上都表现出稳定提升。

尤其是在更小预算下，这种增益更明显——说明它真正补到的是“极限压缩时最容易丢掉的那部分覆盖信息”。






2）GUI grounding 上提升更直观
对 GUI 类任务来说，系统不仅要看到“最显眼”的位置，还要尽量保留更全面的界面线索。

在 ScreenSpot-v2 上，MixKV 对 SnapKV 和 AdaKV 都带来了明显增益，说明“保覆盖”对 GUI grounding 这类任务尤其重要：压缩之后，不只是要保重点，还得保住可操作区域的分布。






3）不只适用于 LVLM，也能迁移到 LLM
MixKV 还进一步验证了纯文本长上下文任务。

这说明它抓住的不是某个视觉任务的小技巧，而是 KV 压缩中更一般的问题：

只按 importance 选，可能会丢掉全局语义覆盖；importance + diversity 联合优化，则更容易保住整体信息结构。






四、为什么这篇工作值得写
这篇工作的价值，不在于它把某个压缩方法完全替换掉了，而在于它指出了一个很基础但长期容易被忽略的问题：

KV 压缩优化的，不该只是“单点价值”，还应该是“整体覆盖”。

一旦把这个问题说清楚，很多现象就都能解释了：

为什么预算越小越容易不稳，为什么多模态场景比纯文本更容易暴露问题，为什么不同 head 不该共享同一套压缩偏好。

更重要的是，MixKV 给出的不是一个难以落地的新系统，而是一条很实用的升级路径：

不推翻已有 KV 压缩器，只是在目标里补上 diversity 这一维，就有机会在几乎不明显增加额外代价的前提下，把结果做得更稳。






从系统优化的角度看，这种工作往往比“只在单一 benchmark 上多刷一点分”更有意义。

因为它真正回答的是一个部署问题：

当我们必须压 KV 时，怎样才能让压缩后的模型，依然尽可能保留原本的信息覆盖与推理能力？

MixKV 给出的答案是：

别再只问哪些 KV 重要，也要开始认真问——这些留下来的 KV，够不够多样，够不够代表整体。
